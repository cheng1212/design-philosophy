# 定 · 闸 · 基座

**一套约束优先的 AI 协作工程哲学**

> 能固定的都固定，不让大模型瞎发挥。
> 改 schema 即改程序行为，不改代码。

> v3（2026-10-06）：吸收 14 个外部工作流/工程哲学的机制，补上"预算、降级、证据链"三块拼图；
> 新增《他山之石》收录别的设计哲学。自评：9.5/10（代拍机制仍待实战验证）。

这套哲学来自两个已落地的工程库的共同实践：
- **novel-library-v2** — AI 写小说工程（选型→点子→世界观→人物→大纲→成文全链）
- **ppt-studio** — 数据驱动的课件生产流水线（一句话→主题→页面→PPTX）

它回答的是同一个问题：**如何让大模型在长链条、高质量要求的生产任务里稳定产出？**

答案不是更好的提示词，而是**把判断前置固化成数据和机器，把选择留给人**。

## 一、三层架构：程序 + 卡库 + 规约

```
规约/          数据定义（JSON schema）——"卡长什么样 / 数据长什么样"
卡库/          知识卡（主题卡 / 页型卡 / 模式卡 / 锚卡…）——"决策是什么"
程序/          执行层（基座 + 工具 + 流程）——"按卡和规约执行"
```

三者不可分：程序按卡库与规约执行，卡库靠程序落地，规约是机器可读的数据定义。

**卡即程序行为**。要改系统行为，先改卡、改规约，程序代码是最后才动的。
规约变更即行为变更，且是版本化、可审计、可回归的。

### 程序层的三分法

```
基座（共享执行层：一处定义，全部共用）
  ↑                    ↑
工具/（检测闸 + 可复用能力）    流程/（按工序生产内容的程序）
```

- **基座**：每个程序都要干的那部分——stdout 编码、路径、退出码、JSON 读写、
  字数口径、卡 YAML 头解析、sha1 指纹。一处定义，全部程序共用。
- **工具**：可复用的能力与检测闸（校验、字数、连续性、数字账、记忆内容检…）。
- **流程**：按工序推进生产的程序（选型、点子、世界观、人物、大纲、成文…）。

铁律：**import 只许向下，不许逆向**（工具不许 import 流程）。
旧函数收编进基座的原则是"**原样搬迁，不重写逻辑**"——先消除分叉，再谈优化。

## 二、七条铁律

### 1. 定 —— 能固定的都固定

- 取值走**闭集清单**：枚举、必填字段、页型模板闭集。
  清单之外 = 扩约定，须经人拍板后写入 `_维度.json`。
- 数据只许出现规约里定义的字段；主题只回答固定的 6 个问题。
- 风格焊死：图表走固定风格（Tufte / Few / Knaflic），主题 CSS 只填 10 个令牌值，不许改规则。
- 目标：让模型的自由度只存在于"被允许变化"的维度里。

### 2. 闸 —— 校验闸必经

- 关键工序转换点必过**数据闸**：P2 数据 → P3 生成之前，必须校验通过。
- 闸的检查项：tpl 闭集、必填、枚举、文件存在、一致性、对比度、令牌完整。
- **FAIL 自动回滚**，不靠人工发现。
- 闸是第三态的：OK / FAIL / 未建（数据源未立项，可由人 `--豁免` 留痕）。
- 退出码是全项目的统一契约：0=OK，1=FAIL/有缺口，2=参数错，3=异常，4=未建。
- **闸分两级**（借自 GitHub Actions required checks / OPA）：
  warn 级只告警不阻塞，deny 级阻塞合并与发布。
  新闸规则先 warn 跑一段时间再转 deny；warn 消耗错误预算，预算耗尽自动转 deny
  （借自 SRE error budget——这是 warn→deny 的升级标尺，不用开会吵架）。
- **每个闸有延迟预算**（借自主干开发）：PR 级反馈 10–15 分钟内；
  超时的慢闸降级为异步 warn，不许拖死流水线。闸越严，批量越要小。
- **闸点存检查点**（借自 LangGraph）：闸通过/失败都留全量 checkpoint，
  回滚 = 回到上一个 checkpoint，而非重跑全链。
- **闸通过附证据**（借自 Argo / dbt）：不只记结论，要附产物——
  失败数据快照、对比图、测试报告。失败行持久化是最好的修闸证据链。
- **每次闸决策写审计事件**：who / 规则版本 / 输入快照 / 判定结果 / 证据，
  不可篡改，供事后验证——否则闸只是当时的断言。
- **闸输出置信度**：机器置信度低 → 自动升级拍板等级（对应分级拍板）。
  "何时升级"本身也是一条可执行的约束。
- **条件通过**（pass-with-debt）：介于过与回滚之间的第三态——
  允许带伤通过，但自动生成技术债卡并记账、限期清偿。
  没有降级语义的闸会被绕过，降级是刚性的安全阀。

### 3. 基 —— 基座层

- 全项目唯一的**口径定义**：字数怎么算、时间怎么写、退出码是什么，
  全部钦定在规约和基座里，不许各程序自创。
- 共享函数收编前先重读——多会话共享仓库里，别人可能刚改过。
- **基座刻意保持无聊**（借自 Boring technology）：基座层只做 schema 注册表 +
  通用引擎 + 闸执行器。基座自身的花哨设计就是对哲学的背叛——
  创新预算只花在业务上，不花在基座上。

### 4. 数 —— 数据驱动，零手写产物

- 人只写**数据**（pages.json、章节数据、主题答案），程序生成**呈现**（HTML、PNG、PPTX、正文）。
- 零手写 HTML，零手写样式。样式 = 主题令牌，内容 = 数据字段。
- **交付物唯一**：PPTX 是唯一的客户交付物，PNG/HTML 只做预览与过程检查。

### 5. 程 —— 操作全程序化

- 凡是能固定的操作——数据扫描、登记、改写、摘要、设定表编辑——**一律程序化**。
- **严禁让 Agent 临场发明扫描/改写逻辑**：模型每次扫的都不一样，程序每次扫的都一样。
- 提取逻辑（正则/解析器）是**版本化维护的系统资产**，集中在程序内带版本注释，
  每轮迭代改程序、跑回归，不许现场写。**程序有问题 → 改程序。**
- **可重试的闸必须幂等**（借自 Airflow）：重试安全是闸的前提——
  状态不符直接结束，先删分区再写，重跑不产生副作用。
- **纵深防御**（借自 Conventional Commits）：hook 便民（本地先拦）+
  CI deny（服务端终审）。越不可逆的闸越要严——发布闸一旦放行便不可逆。

### 6. 跑 —— 跑即完善，缺陷必进机器

- **产出是试验台**：书的每一章、课件的每一页，都是系统的压力测试样本。
- PASS / WARN 是次要的，真正的交付物是"这批暴露了系统哪些脆弱点、修掉了哪些"。
- 验证方审核 / 写手反馈出的系统性问题，一律落成"闸 / 自检项 / 只读工具"三选一，
  改完要有可复现的验证命令。**不许靠"下一批注意"收尾。**
- 每批必跑验证仪式：自检（硬错 0）+ 内容检 + 抽查 + 抽审。
- **预算也是闸**（借自 Shape Up appetite / SRE / Erlang restart intensity）：
  token / 时间 / 重试次数三类预算闸，超预算即 deny 并升级人工。
  Shape Up 的 appetite 问的是"值得花多少时间"而非"要多久"，
  circuit breaker 周期结束未做完不默认延期——AI 任务同理，预算耗尽即停，不许悄悄透支。
  滑动窗口内失败超 N 次 → 放弃并向上传递（Erlang supervision trees）：
  约束优先防"已知的坏"，监督树治"未知的崩"，两者都要。

### 7. 拍 —— 拍板文化

- 关键决策点**显式停下等人**：选型要看预览图再拍板，总览要整篇过审再导出。
- **不留痕不许进下一步**：选型记录（意图/候选/选中/理由）不写，不许写数据。
- 一条命令走一步，状态落盘，可续跑；随时可查进度。
- **立项闸**（借自 Amazon Working Backwards）：PR/FAQ 即立项杀闸——
  约束优先管"生产得对"，立项闸管"值得生产"。写不清楚客户价值，就不进生产链。
- **柔性拍板**（借自 LangGraph interrupt）：闸是"校验不过则回滚"（刚性），
  中断是"暂停待人决断"（柔性）——一柔一刚，互补实现分级拍板。

## 三、协作协议：多方 / 多会话如何不打架

当多个 Agent（或人 + Agent）共享一个仓库时：

- **信号文件是进度的唯一真源**：`写手信号.json` / `验证方信号.json`，
  状态机驱动（放行 → 写作中 → 待审 → 审核中 → 放行/退回）。
- **只写自己的信号文件**，互不代写；跨方字段污染当场报警。
- **动作单元幂等**：状态不符直接结束，不抢戏。
- **防并发**：占坑（"审核中"状态）+ 一轮没跑完不重复开；轮询间隔与任务时长要匹配，
  否则并行实例会打出分叉提交。
- **不擅自提交、不擅自推送**；`git add` 只列自己的显式路径，绝不 `add -A`
  （工作区有别人 WIP 是常态）。

## 五、适用边界

这套哲学不是银弹，它有明确的代价——v2 用补丁一把代价显性化：

- **每个任务立项时先定档**（见六、补丁一），定档结果即成本声明：
  L3 重型 = 高成本高保障，L1 轻量 = 低成本快试错。
- **当"稳定压倒一切"时用 L3**（长链条、高 stakes、可复用资产）；
  **当"快和试错"更重要时用 L1/L2 + 破例通道**（见六、补丁三）。
- **拍板瓶颈**用分级拍板对治（见六、补丁二）：不是每道闸都要人来守。
- **刚性的代价**用破例通道对治：闭集保下限，沙盒探上限，突破有正式流程可走。

一句话：**没有"用或不用"的二选一，只有"用哪一档"的定档题。**

## 六、从 8.5 到 10：四个补丁

v2 自评 8.5/10，扣分在三处：**仪式成本**、**拍板瓶颈**、**刚性压上限**，补了前三个补丁。
v3 吸收外部工作流哲学的机制，补第四个补丁：**预算与降级**——此前闸只有正确性维度，
缺时间 / 资源 / 失败次数三类预算。以下四个补丁逐一对治——且每个补丁自带防滥用闸，
因为补丁本身也必须服从这套哲学（能固定的都固定）。

### 补丁一：分级仪式（对治仪式成本）

- 三档封顶：**L1 轻量 / L2 标准 / L3 重型**，不许自创第四档。
  - L1：单步或一次性任务——只过数据闸，不走全链，不写交接文档。
  - L2：常规生产——走全链，免交接文档（留痕在状态文件里）。
  - L3：长链条 / 高 stakes / 可复用资产——全链 + 交接文档 + 验证仪式。
- 定档规则写进规约（`任务分级规约.json`）：四个维度打分——
  链条长度、可复用性、质量要求、返工代价 → 自动定档。
- **定档本身是一道闸**：任务立项先过"定档闸"，定档结果留痕、可复核。

### 补丁二：分级拍板（对治拍板瓶颈）

- 拍板点分级：
  - P1 常规拍板（选型预览、总览过审）→ 可授权**代拍**；
  - P2 扩约定 / 豁免 → 必须人拍；
  - P3 方向与架构 → 必须人拍 + 书面留痕。
- 代拍三条件：
  1. 代拍标准写进规约（代拍标准卡，白纸黑字）；
  2. 全程留痕、结果可审计、可回滚；
  3. 代拍错一次即降级回人拍——**代拍资格本身也是一道闸**。
- 超时默认通过：L1/L2 的 P1 拍板可设超时默认通过，人事后抽查；
  抽查发现问题 → 该 Agent 代拍资格暂停。
- 本质：**拍板也是一道可分级的闸，不是每道闸都要人来守。**

### 补丁三：破例通道（对治刚性压上限）

- **沙盒实验区**：清单之外的想法，先在沙盒跑，不污染主链。
- 破例流程四步，全程留痕：
  破例申请（理由 + 预期 + 评估标准）→ 沙盒验证 → 效果评估 →
  有效则走扩约定流程进规约，无效则归档为"已知无效"（也是资产）。
- 铁律：**沙盒产出不得直接进入交付物**；想进交付物，重走全链 + 人拍板。
- 破例通道不是绕过闸的后门，而是**把"突破"变成流程的一部分**。

### 补丁四：预算与降级（v3 新增，对治"闸只有正确性维度"）

- **三类预算闸**：token / 时间 / 重试次数，超预算即 deny 并升级人工。
  错误预算分级油门（SRE）：预算 >50% 自由跑，<25% 只修闸不跑新任务，
  耗尽则冻结——这是 warn→deny 的升级标尺。
- **条件通过 pass-with-debt**：允许带伤通过，自动记技术债账本、限期清偿。
  没有降级语义的闸会被绕过。
- **置信度驱动升级**：闸输出机器置信度，低置信自动升级拍板等级。
- **防滥用**：预算数字写进规约，不许临场改；技术债账本公开可查，
  逾期未清偿的债自动升级为 deny——欠债也要有闸。

### 补丁的补丁：自我批判

1. **分级增加复杂度，违背"简单"？**
   → 分级规则固定在规约里，定档自动执行，不许临场发明第四档。
   复杂度被关进规约，而不是散在每次判断里。
2. **代拍重新引入"模型瞎发挥"？**
   → 代拍标准必须比人拍更严，且代拍资格可撤销。守闸的人可以换，但闸不能松。
3. **破例通道被滥用成后门？**
   → 沙盒与主链物理隔离（目录 / 分支隔离），产出进交付物必须重走全链。
4. **补丁本身未经验证？**
   → 按"跑即完善"：先在小任务上试跑分级，抓缺陷修进机器，再推广。
   补丁也要跑。

## 八、术语表

- **卡**：知识卡，机器可读的决策记录（主题卡、页型卡、模式卡、锚卡、素材卡…）
- **规约**：JSON schema，卡和数据的数据定义
- **闸**：工序转换点的强制校验程序
- **基座**：共享执行层
- **跑**：按流程完整执行一次生产（如跑完一本书、跑完一套课件）
- **拍板**：人在关键决策点的显式确认
- **留痕**：决策与理由落盘记录
- **定档**：任务立项时按分级规约确定仪式档位（L1/L2/L3）
- **代拍**：Agent 按规约中的代拍标准代替人执行 P1 拍板
- **破例**：清单之外的尝试走沙盒验证的正式流程
- **沙盒**：与主链隔离的实验区，产出不得直接进入交付物
- **错误预算**：允许失败的配额（SRE）；warn 消耗预算，耗尽则 warn 自动转 deny
- **条件通过**：pass-with-debt，带伤通过 + 自动记技术债账本
- **审计事件**：每次闸决策的不可篡改记录（who / 规则版本 / 输入快照 / 结果 / 证据）
- **预算闸**：token / 时间 / 重试次数三类预算约束，超预算即 deny
- **检查点**：闸点的全量状态快照，回滚 = 回到上一个检查点
